# 5.22.0

A successful platform call has already done its work. When the gateway returns a saved result the agent cannot read,
retrying repeats that work, so the SDK now tells the agent not to.

- New `PlatformCapabilityResult.Read<T>`: reads a successful result as the expected type. An unreadable result throws
  `PlatformCapabilityException` with `FailureCode = "platform.contract_violation"`, `Retryable = false`, and a message
  that says the action already happened and must be escalated, not retried. An empty result is still a
  `ValidationFailed` with no failure code. `PlatformCapabilityResult.IsContractViolation(exception)` recognizes it.
- Every typed client (`PlatformCapabilityClient.InvokeAsync<TRequest, TResponse>` and the work, Git workspace, source
  control, artifact, personal to-do and infrastructure clients) reads results through it. Before, an unreadable
  result was a generic "returned invalid JSON" failure with no retry hint.
- `McpAgentRuntimeClient.InvokeAsync` logs a warning and continues when a successful result carries
  `_meta.csweet.contractViolation`, which C-Sweet sends when a handler's saved result breaks the tool's declared output
  schema. The typed read then decides: the agent continues when the result reads as its expected type and escalates
  without a retry when it does not.

Why: QFN Games, 2026-11-11. The gateway declared `request_project_resource` as returning a list. Each request was saved
and then reported as a failure, so the Technical Director could neither continue nor safely retry. C-Sweet now derives
output schemas from result types and returns committed results with the contract-violation marker; this SDK release is
the agent side of that change.

No breaking API change. Agents pick it up by rebuilding against 5.22.0.

Tests: `PlatformCapabilityResultTests`.

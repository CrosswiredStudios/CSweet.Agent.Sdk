# 5.19.0

Completes Git delivery for agents that must survive a runtime replacement.

## `context.Platform.Git.PushCheckpointAsync`

New, additive. The Git equivalent of `UploadCheckpointAsync`:

```csharp
var receipt = await context.Platform.Git.PushCheckpointAsync(
    workspace, assignmentRevision,
    new GitWorkspaceCommitRequest("chore: checkpoint before a larger runtime", authorName, authorEmail),
    cancellationToken, commandClass, inputFingerprint, resumeSummary);
throw new WorkloadResourceHandoffException(new(memoryMb, receipt, commandClass, inputFingerprint, reason));
```

It commits every change, pushes the work branch, and asks the platform to record the pushed commit as the source checkpoint. The platform records it only after confirming that the work branch is at that commit. The receipt's `Digest` is the commit. The command class, input fingerprint and resume summary are recorded exactly as they are for a snapshot checkpoint.

The checkpoint commit stays on the work branch and is part of what reviewers see.

## `CloneAsync` returns resume state

`CloneAsync` now fills `GitWorkspaceResult.ResourceProfiles` and `ResumeSummary`, as `MaterializeAsync` does. A replacement runtime clones, finds the pushed work checked out, and reads the notes left with the last checkpoint.

`GitWorkspaceSyncRequest.PushedCommitSha` is new and is set only by `PushCheckpointAsync`.

## Compatibility

No manifest change and no new capability name: both calls use the existing `git.workspace.sync.v1` capability with the new directions `checkpoint` and `resume`. A platform that names a work branch but does not know those directions rejects them, so `CloneAsync` fails there; upgrade the platform and the SDK together. The snapshot calls are unchanged.

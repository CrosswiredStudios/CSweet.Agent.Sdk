# 5.25.0

Interactive behavior is observed with one shared runner and judged outside the page.

From Super Awesome Games ticket VGD2A04892DB-38 (2026-11-13), which failed QA twice in a row on the same spike harness.

- **First round.** The page reported a voice peak of 5 against a cap of 4, yet printed "0 failed".
- **Second round.** The page's adjacency check read the planned brick path, while the bricks that were actually hit
  included a diagonal step.
- **What both rounds had in common.** The engineer's only browser tool proved that the page loaded. Every measured
  value in the observation record came from reading code. QA was the only role able to observe the build, and it found
  one mismatch per round.

## Changes

- **`BrowserScenarios`** (see `docs/browser-scenarios.md`): the browser scenario contract
  (`window.csweetScenarios.run()` returns events plus expected and observed checks).
  - `RunnerScript` is the author's runner: real Chromium over Node's CDP client, no npm dependency.
  - `PlaywrightScript` is QA's independent run. Both share one evaluator.
  - The evaluator ignores any result the page declares. A check whose observation cites no emitted event fails.
  - The runner regenerates the measured section of named observation records.
  - `ReadRecord`, `Compare` and `Summarize` let QA diff its own run against a record.
  - `Command`, `Guidance` and `AssignmentNote(planning)` support authoring agents.
- **Technical review.** `BranchDiffTechnicalReview` requires a passing browser-scenarios receipt when planning
  declares `browser-interaction`, alongside the browser-smoke receipt. The model is asked whether each check measures
  its criterion from emitted events.
- **Corrective tickets.** `DeliveryCorrectionCoordinator` gives corrective tickets a description that lists every
  inherited finding. It also says the whole task is re-verified against all of its criteria.
- **Dependencies.** `CSweet.WorkManagement.Contracts` 5.6.0, which provides the receipt command, its matcher and
  `ScenarioRecords`.

Agents that author or verify interactive web output (Engineer, Software Developer, QA, Technical Director) need updates
to use this. Tickets that declare only browser-smoke are unaffected.

Validation: see the C-Sweet project's observed-behavior implementation log for test counts. The new tests include a
real-Chromium run of the runner against a fixture page.

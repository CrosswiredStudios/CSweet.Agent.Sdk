SDK 5.0.4 runs ordinary networked npm restoration as a durable guest service with no overall installation deadline. Short compute commands launch or observe the job; runtime restarts reuse its stable identity and only a completed successful job receipt permits tests/build. A lost launch reply leads to observation rather than another install. The VM lease, explicit destruction and npm's own completion/failure remain authoritative.

`AggregateSourceReview` partitions large aggregate source inputs before criterion assessment. `DeliveryScopeReview` removes duplicate document bodies and transient prior outcomes, supplies source inspection evidence to the criterion and consistency steps, and retains all source findings. Inspection checkpoints bind exact source/planning identities and are authorized again before reuse and persistence. This bounds request input without reducing the 128k output allowance or treating summaries as test execution.

This document describes SDK internals. Agent authors should use the callback API and must not depend on these details.

The SDK uses private Streamable HTTP `/mcp`. `initialize` reads a one-use workload token from the configured secret file. It sends runtime, tick, installation, organization, package identity, and version metadata. The returned token is held only in memory, renewed after five minutes, and discarded on disconnect.

The worker long-polls `csweet/work/claim` for at most 25 seconds, runs bounded concurrent callbacks, renews each 60-second lease every 20 seconds, reports bounded progress, and completes/fails using the attempt and lease token. Broker control requests have a 30-second client boundary, while capability calls have a three-minute boundary so a stalled HTTP exchange cannot permanently wedge the work loop. Event leases carry both the delivery `workId` and the originating domain `eventId`; the worker rejects event work without the latter. It reconnects with bounded jitter and never invents work from notifications.

`ConfigurationUpdate` is reserved control work. The worker drains ordinary callbacks before
applying it, ignores stale revisions, atomically swaps the settings snapshot, invokes the typed
`OnConfigurationChangedAsync` hook, and acknowledges the applied revision and digest. Settings
are platform-owned: agents can read snapshots but cannot persist defaults or employee overrides.

`tools/list` is the only descriptor source. The SDK caches descriptors only by grant revision. Typed calls still resolve a live descriptor and the gateway reauthorizes every call. `modelVisible` controls conversion to `AITool`; transport and lifecycle tools are never exposed to models.

Git workspace v2 typed clients intentionally omit repository and ref selection. Do not add clone
URLs, connection IDs, provider installation IDs, credentials, branches, base refs, or arbitrary
commit SHAs to prepare requests. The authoritative assignment revision is required on every
workspace operation. `PlatformSourceControlClient` exposes only bounded repository intent and
exact-SHA decisions; it is not a general GitHub administration client.

Source-control provider authentication belongs to separately deployed trusted services. SDK code
must never inspect `.git`, inject credentials, invoke authenticated Git, mint provider tokens, or
offer a local fallback. A provider outage is reported as a bounded platform capability failure.

Runtime methods:

- `csweet/session/renew`
- `csweet/work/claim`
- `csweet/work/renew`
- `csweet/work/progress`
- `csweet/work/complete`
- `csweet/work/fail`
- `csweet/runtime/complete`

Never expose session/workload/lease tokens, the endpoint, `HttpClient`, JSON-RPC, or MCP objects through public authoring APIs. Transport interfaces remain internal. Tests use `AgentTestRuntime`, which deliberately models callbacks and capability grants rather than wire details.

Protocol extensions must be additive within 2.x, server-advertised, size-bounded, authenticated, non-model-visible, and covered by replay/restart/cancellation tests. A change to identity, authorization, lease, completion, or credential semantics requires a new protocol minimum and coordinated security review.

Manifest `connections` and `setup` are additive authoring contracts, not authority. The importing
platform must repeat validation, resolve provider profiles from its trusted registry, render only
known native components, and restrict setup callbacks to a bootstrap grant containing exactly the
declared setup capabilities. The normal agent runtime, model access, memory, chat, organization
data, filesystem, and ordinary network grants remain unavailable until platform activation gates
transition the installation to ready.

For progressive staffing, ReviseWorkItemPlanningRequest accepts optional StageAssignments and AccountableOrganizationUserId. Null assignments preserve existing ownership; explicit replacements are validated by the host against stage policy, ticket requirements, roster and profile evidence. The agent cannot use a planning revision to bypass execution immutability or eligibility checks.

## Broker connection recovery (3.48.1)

`McpAgentRuntimeClient.SendAsync` retries connection interruptions for `csweet/llm/start`
and `csweet/llm/read` up to three sends within the original request timeout and cancellation token.

error code). These bounded diagnostics omit payloads and exception messages so the runtime log tail
can retain useful evidence without copying request contents or credentials.

Hierarchical task technical review uses only bounded reads and has no old-review fallback. `RepositorySourcePolicy` gives coding harnesses a shared source-delivery contract. Gitignore processing happens in the trusted snapshot publisher using Git's own matching semantics and retains tracked-file behavior.

`TechnicalReviewJson.ReadAsync` transmits a strict response schema through `PlatformChatRequest.ResponseSchema` and preserves the provider finish reason. It validates JSON syntax, duplicate and unknown properties, required fields and semantic bounds. One correction may replace invalid model content; transport and cancellation failures propagate. Repeated invalid content reports the page/final operation and finish reason without accepting a verdict.

`DeliveryTaskTechnicalReview` persists each validated page in operating state with a policy and candidate/planning/scope identity. Resume reauthorizes each current page and verifies its text hash. Final synthesis resolves every identified blocker explicitly, cites reviewed offsets and covers every exact criterion. Overflow rejects safely after complete coverage. Retained page state is evidence, never an execution grant; final authorized source, target, planning, delivery and reviewer reads remain mandatory.

SDK 4.4.0 no longer asks models to reproduce commit hashes or offsets. The validated read loop
attaches those identities to page summaries, and the final result uses the authorized reference
pair. This prevents the observed source/target reversal from blocking review without trusting
model-generated provenance. Models still supply and validate substantive review content; changed
or incomplete reads and approvals with unresolved findings fail closed.

## Artifact QA rework recovery (4.4.0)

The platform dispatcher selects only the latest attempt of the current traversal's author for artifact QA. ArtifactDeliveryReview rejects ambiguous producer history before any artifact read. Authorized retry evidence is supplied to the reviewer, which must distinguish API claims from independently supported source evidence and proposed performance targets from measurements. Platform grant reconciliation must load producer attempts even when invoked from a fresh inbox-claim context; partial EF navigation state cannot revoke active review grants.

## Routine incident recovery (4.4.0)

The platform retains routine incidents with their reporting manager and schedules durable reviews.
`IncidentOwnerReport.RequiresOwnerInput` and `OwnerInputReason` gate human attention. Older
reports are refreshed rather than treated as owner decisions. `RoutineRecoveryFunction` uses
stable episode/operation/target keys across event duplicates and source refreshes. Model text
cannot certify a queued/running retry; the platform derives it from correlated execution records.

## Managed compute dependency restore (5.0.4)

`ExecuteComputeCommandRequest.NodeDependencies` binds public npm tarballs to the exact candidate lockfile. `DeliveryNodeDependencies.Read` accepts npm lockfiles 2/3, registry.npmjs.org HTTPS tarballs and SHA-512 integrity; unsupported registries, local/git dependencies and conflicting or missing integrity fail closed. This optional operation requires current installation and scoped `compute.execute.v1` plus `network.outbound.v1` authority. Declarations are requests, never grants. An npm-only scoped grant does not authorize general VM networking or a public endpoint.

The provider validates both recorded grants at dispatch and rechecks current authority during download/transfer and before execution. It rejects private/host/metadata DNS destinations, redirects, credentials, unbounded bytes and integrity mismatches. Packages are never extracted or executed on the provider host. Verified tarballs populate a guest-only offline npm cache; `npm ci` checks the actual source lockfile before tests/build. Unknown command outcomes remain fenced and cannot silently replay. Installation is not acceptance: exact-source tests, web build, HTTP proof and independent review still follow.

## Delegation project context (5.5.1)

`DelegationRuntime.BindExecutionContext` restores the current authorized delegation's project, team and task context before nested classification and native callbacks. Both the incoming message and event envelope carry the same context. Conflicting organization, project, team or task identities fail closed. Metadata restoration creates no execution, artifact, board or repository grant; every capability still reauthorizes its current resource.

# 5.18.0

Lets an agent publish the commits it pushed with git.

## `PublishGitWorkspaceRequest.PushedCommitSha`

New, additive. Set it to the commit returned by `context.Platform.Git.PushAsync`:

```csharp
var pushed = await context.Platform.Git.PushAsync(workspace, assignmentRevision, cancellationToken);
var publication = await context.Platform.Git.PublishAsync(
    new PublishGitWorkspaceRequest(workspace.WorkspaceId, assignmentRevision, commitMessage, title, body, idempotencyKey, validations)
    {
        PushedCommitSha = pushed
    },
    cancellationToken);
```

The platform then publishes the work branch as it stands. It accepts the request only when the branch tip is exactly that commit and the commit descends from the assignment's base commit. It creates no commit, so `CommitMessage` is unused; the agent's own commits are what reviewers see. The review diff, file-lock check, validation evidence and publication record are the same as for a snapshot.

Naming the commit makes publication explicit: a push that lands after the agent decided to publish is not published by accident, and a workspace that holds both an uploaded snapshot and pushed commits is never ambiguous.

When the field is `null`, the uploaded snapshot is published as before.

## Compatibility

No manifest change and no new capability name. Requires a platform that publishes pushed commits. An older platform ignores the field and publishes the uploaded snapshot, which fails for a workspace that pushed with git because its work branch has moved; use the field only when `GitWorkspaceResult.BranchName` was provided.

# 5.23.0

Fixes a stall between sprints seen at QFN Games on 2026-11-12. Sprint 1 (a Phaser dependency pin and a technical
document) completed, but its increment acceptance was blocked at build readiness with "The candidate needs a root
Dockerfile … or a dependency-free static index.html", and the Producer then asked its model the same question about
every 45 seconds while Sprint 2 stayed empty.

## Build readiness reads the plan's own declaration

- `DeliveryComputeTest.RunnableOutputInScopeAsync` (new): true when a Code task in the increment declares browser smoke
  or predates verification declarations; false only when every Code task explicitly declares no browser evidence.
- When the candidate has no runnable entry point and nothing runnable is in scope, the compute-test readiness stage now
  completes as approved with "No test application to start", without a test link. Technical review and QA still assess
  every criterion. When runnable output is in scope, the finding is unchanged.
- `DeliveryComputeTest.TrySelectMode` (new) returns null for a candidate with no runnable entry point;
  `SelectMode` keeps throwing `DeliveryComputeTest.NoRunnablePackage`.
- Requires the C-Sweet AgentHost that accepts such a readiness result. Older platforms reject it, and the stage reports
  the same finding as before.

## Delivery corrections are decided once

- When a correction's only findings are "no runnable test package" and nothing runnable is in scope,
  `DeliveryCorrectionCoordinator` asks the platform to re-run acceptance (`work.delivery.recover.v1`) instead of planning
  a repair. On an older platform it falls back to ordinary planning.
- A multi-source selection now has a stable fingerprint (correction, findings, exact source revisions). Model prose no
  longer decides whether something changed, so the coordinator's own wait write no longer wakes it.
- When the model answers `NeedsPlanning`, or no planning model is configured, the coordinator asks the owner once
  (`DeliveryCorrectionCoordinator.SourceDecisionType`): fix it in one of the completed tasks (a corrective task is added
  for that task's owner) or keep the increment waiting. The owner's choice is applied on the next reconcile, and the
  model is not asked again for the same situation. Without decision access the wait still records the fingerprint, so
  the model is asked once.

## Git delivery falls back to a snapshot

When the platform names a work branch, `MaterializeAsync` clones the repository with git. If that clone fails and
nothing has been written to the workspace directory, it now downloads the snapshot instead of failing the assignment.
This covers a runtime image without git and an Office that does not relay Git requests yet (before Office 0.15.0). The
workspace then stays a snapshot workspace for its lifetime in that runtime. The runtime writes one line to standard
error starting with `csweet.git.fallback`, with the workspace and git's reason. Failures after a successful clone (a
refused push, an oversized exchange) are not masked.

`GitForwarderEndToEndTests` (new) runs the real git client through the real loopback forwarder against git's own
stateless-rpc programs: clone, a 3 MiB push, a no-op save and a resume in an empty directory, and confirms that git
without the forwarder secret is refused.

Agents pick this up by rebuilding against 5.23.0: the Engineer and Software Developer for the Git fallback, the Producer for corrections, the Technical Director for build
readiness.

Tests: `DeliveryComputeTestTests`, `DeliveryCorrectionCoordinatorTests` (848/848 SDK tests pass).

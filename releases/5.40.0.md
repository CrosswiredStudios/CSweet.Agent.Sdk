# 5.40.0

Adds a retry-later outcome for personal to-do work, so a failure that may clear by itself no longer ends as a permanent block.

- `PersonalTodoResult.RetryLater(failure)` is a new outcome beside Completed, WaitingUntil and Blocked. Use it when an attempt failed for a reason that may clear without anyone acting: a model reply that was not accepted, a platform conflict, or facts that changed during the attempt. Use Blocked when a named person or authority must act, and WaitingUntil when someone else owns the next step.
- The runtime retries the same failure after 1, 2, 5, 15 and 30 minutes. If it still fails, or ten retries of any kind happen within six hours, the item is Blocked with the exact last failure so its manager sees the real cause. A failure older than six hours starts a new budget.
- An unhandled exception in a personal to-do handler now goes through the same retry budget and keeps its exception type and message. Previously the claim was released and the item was later blocked as "execution stopped unexpectedly". Cancellation and resource handoff behave as before.
- The budget is kept in the agent's operating state under `personal-todo-retry:v1:<item id>`. An agent without operating-state access keeps the previous release-and-fail behavior.

Agents pick this up when they reference 5.40.0. No manifest change is required for agents that already use operating state.

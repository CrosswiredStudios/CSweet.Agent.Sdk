# 5.12.0

Adds an optional planning-client overload to `DeliveryCorrectionCoordinator.ReconcileProjectAsync` while preserving the existing signature. Managers can continue a retained multi-source rejection by mapping every finding to one declared source using quoted accepted scope and finding evidence. The model has no tools and cannot create work or authorize execution.

The coordinator validates complete finding coverage, one in-plan source and distinctive verbatim evidence, rechecks current plan/task revisions, and persists the source through the existing manager-authorized correction API before creating corrective tasks. Lost selection/task responses and cold restarts reuse the saved selection. Missing, conflicting, cross-source, malformed or unavailable evidence retains an explicit manager wait. Cancellation propagates.

Normal staffing, current grants, independent QA, unchanged acceptance and separate-sprint preflight remain required. No contract version, platform migration, network permission or reporting-budget change is needed. Requires Work Management Contracts 5.3.0 and the corrective-delivery platform support shipped with SDK 5.11.0.

Verification includes the two-input Prism Break scene/dependency case, selection-before-execution ordering, replay after lost responses, stale plans/tasks, denied selection, provider failure/timeout, caller cancellation, invalid citations and genuine ambiguity. See the C-Sweet corrective-delivery plan for release verification and live rollout status.

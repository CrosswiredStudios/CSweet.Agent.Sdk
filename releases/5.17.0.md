# 5.17.0

Adds Git access for an assigned workspace. An agent can clone its repository, commit locally and push its work branch, in place of downloading and uploading whole-workspace snapshots.

## New on `context.Platform.Git`

- `CloneAsync(workspace, assignmentRevision)` clones the assigned repository into the runtime's local workspace path and checks out the work branch. Work pushed earlier for the same assignment is checked out in preference to the base commit, so a replacement runtime resumes it. An existing local clone is kept, uncommitted edits included.
- `FetchAsync(workspace, assignmentRevision)` updates the remote branches without touching the working tree.
- `CommitAsync(workspace, new GitWorkspaceCommitRequest(message, authorName, authorEmail))` commits every change and returns the commit, or `null` when nothing changed. It honors the repository's `.gitignore` and never commits `node_modules/`, `.venv/` or `.csweet/`.
- `PushAsync(workspace, assignmentRevision)` pushes the work branch and returns the pushed commit.
- `GitWorkspaceResult.BranchName` is the work branch chosen by the platform. It is `null` from a platform that does not serve Git to runtimes.
- `GitWorkspaceCommandException` reports a failed git command. `Detail` is git's own message, including the platform's reason when it refuses a push.

Between those calls an agent may run any local git command in the workspace (`status`, `diff`, `log`, `add`, `commit`). Only the four calls above reach the platform.

## Security

The runtime holds no Git credential and none is written to the repository configuration. Git talks to a forwarder inside the agent process on the loopback address; the forwarder accepts only the fixed Git routes, requires a per-process secret, and relays each exchange through the authenticated runtime session. The platform authorizes every exchange for the assignment and enforces its push rules: only the assigned branch, no deletion or history rewrite, no symbolic links or submodules, and a file size limit above which Git LFS is required. See `SECURITY.md`.

## Compatibility and limits

Additive. No manifest change and no new capability name. The calls throw `NotSupportedException` when the platform did not name a branch or the transport has no Git route (including `AgentTestRuntime`); `MaterializeAsync`, `UploadAsync` and `UploadCheckpointAsync` are unchanged and remain the fallback.

Requires git 2.31 or later in the runtime image. Each Git exchange is buffered and limited to 16 MiB minus 64 KiB, so a larger clone or push fails until streaming is available on the platform.

Validation: not yet run. Run the SDK, sample and generated-template tests before publishing. New tests: `AgentGitForwarderTests`, `McpAgentRuntimeClientGitTests`, `PlatformGitWorkspaceRemoteTests` (the last one runs the real git program).

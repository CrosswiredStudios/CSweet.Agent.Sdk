# 5.22.1

Progress is telemetry. A lost or rejected progress report must never stop work.

- **A failed report keeps its number.** `AgentRuntimeContext.ReportProgressAsync` (the lease progress reporter)
  now advances its sequence only after the platform accepts the report. A failed report is resent with the same
  number. Before, the number was used up first, so after one failed report every later report reached the
  platform as a gap and was rejected for the rest of the attempt.
- **Model-call status reports are best-effort.** The "LLM request received / queued / generating" progress that
  `McpAgentRuntimeClient` sends while it polls an inference job no longer fails the model call when the report is
  rejected. Cancellation still stops the call, and a revoked lease or ended attempt still fails the next inference
  read.

Why: QFN Games, 2026-11-11. One progress report from the Engineer was lost (its workspace progress swallows
failures). The next model call's status report was then rejected with "Progress sequence numbers must be strictly
monotonic without gaps", the model call failed twice, and ticket `VG58E8BFBD4D-29` was blocked. C-Sweet now also
accepts gaps and treats a resent number as a duplicate, so this can't recur even with older agents.

No API change. Agents pick it up by rebuilding against 5.22.1.

Tests: `PersonalTodoLeaseLifecycleTests` (a failed first report is resent with the same number),
`InferenceStatusProgressTests`.

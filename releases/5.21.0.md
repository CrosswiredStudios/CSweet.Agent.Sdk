# 5.21.0

Adds `AgentModelJson`, one way for agents to read a JSON decision or review from a model and correct it in the same
conversation.

- `AgentModelJson.ReadAsync<T>(client, messages, request, ct)` sends the messages (with a structured-output schema when
  `request.Schema` is set), parses one JSON object, runs `request.Normalize`, and returns the result.
- A reply that is empty, not JSON, truncated by the output budget, or rejected by `Normalize` (by throwing
  `AgentModelJsonException`) is sent back with the model's previous answer and the exact problem, up to
  `CorrectionLimit` times (default 2, at most 5). Only the latest rejected reply is kept, so corrections do not grow
  the conversation.
- When corrections are used up it throws `AgentModelJsonException` with `Problem` (the last problem) and `Attempts`.
- `AgentModelJson.Parse<T>` reads bare JSON, fenced JSON or the outermost object in prose, and names the problem
  when there is none. `AgentModelJson.SchemaFor<T>()` exports a schema from the serialization contract.

Why: agents parsed model JSON by hand and failed the whole turn when one field disagreed with another, even where code
could derive that field. On 2026-11-11 QFN Games' production brief stalled because the Creative Director rejected three
substantive reviews over checklist bookkeeping, and each retry started a new review instead of repairing the last one.
Creative Director 4.1.2 fixes that case with its own copy of this loop; other agents should move to this helper.

No existing API changed. The internal technical-review reader is unchanged.

# 5.24.0

Compute evidence archives no longer have a 4 MiB cap.

- `PlatformComputeClient.ExportEvidenceAsync` accepts any positive archive length. `ReadEvidenceAsync` no longer
  rejects completed artifacts over 4 MiB.
- New `PlatformComputeClient.ReadEvidenceToAsync(operation, destination)` streams the archive page by page into a
  caller stream and verifies the final SHA-256, so large archives need not be held in memory. `ReadEvidenceAsync` now
  uses it.
- The cap came from Core carrying the whole archive inside the provider's signed result and the operation's result
  row. C-Sweet now stages the archive in 1 MiB parts under the live dispatch (`ComputeEvidenceParts`) and verifies it
  before accepting the result. Older Core and providers still carry archives up to 4 MiB inline; a larger archive needs
  both updated.

Validation: SDK test suite (see the C-Sweet project's implementation log for counts).
